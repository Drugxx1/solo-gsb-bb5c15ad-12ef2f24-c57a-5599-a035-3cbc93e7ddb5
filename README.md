# 舞台换景口令沙盘

舞台换景口令的图编辑与排程沙盘：在画布上编排口令节点与前置约束（前置完成后至少等待 N 秒），系统实时重算每条口令的最早执行时间；出现环依赖时保留上次有效排程并红色高亮成环路径。支持按排程模拟执行（暂停 / 继续 / 重置），编辑导致的排程变化会同步到尚未执行的口令。可在工具栏启用「开场截止」：按全部后继约束反向倒排每条口令的最晚开始时间与浮动时间，浮动最小的关键链金色高亮，截止早于最短工期时显示超期秒数并保留负浮动。工具栏可设置「班组人数」、口令侧栏可设置每条口令的「用人数」，底部「班组排程」面板在前置/等待约束之上叠加班组容量，生成不抢占的可行排程（可填入已排定口令之间的空档）。选中口令或前置约束可在侧栏进行「增量预演」：输入不小于当前值的时长或等待秒数，在内存克隆图上试算（不保存），对比现行与试算的总工期、开场截止超期量及被推迟口令的传播路径，点「应用」才写入。数据持久化在本地数据卷中。

## 启动（单条命令）

```bash
docker compose up --build
```

启动完成后访问：**http://localhost:8080**（端口 `8080`）

> 依赖安装、前后端构建、示例数据初始化均随镜像构建与容器启动自动完成，无需额外步骤。
> 停止：`Ctrl+C`；后台运行可用 `docker compose up -d --build`。

## 使用说明

- **添加口令**：工具栏「＋ 添加口令」。
- **建立前置约束**：从口令节点右侧圆点拖线到目标口令；选中连线后可编辑“前置完成后至少等待秒数”。
- **编辑口令**：点击节点，在右侧栏修改名称与持续时长；每次修改都会实时重算全图最早执行时间。
- **开场截止倒排**：工具栏勾选「开场截止」并输入秒数，系统按全部后继约束反向计算每条口令的最晚开始时间与浮动时间，与最早排程共同展示（节点、侧栏、甘特图）；浮动最小的口令与约束边构成关键链并金色高亮。截止早于最短工期时，工具栏显示超期秒数，浮动如实显示为负值，便于定位无法按时完成的链路。截止设置随口令图一起持久化。
- **环依赖**：若约束构成环，顶部出现警告，排程与倒排结果回退为上次有效结果，成环的节点与连线红色高亮。
- **班组排程**：工具栏「班组人数」设置正整数容量（缩小容量时自动把超限口令的用人数夹紧到新容量），选中口令后在侧栏设置该口令的「用人数」（0 到班组人数之间的整数）。底部「班组排程」面板随编辑实时重算：每轮从全部前置已排定的口令中，先按前置允许开始时刻（前置结束 + 等待的最大值，无前置为 0）、再按口令 ID 字典序选一个，把它放入不早于该时刻、整个持续区间内总用人数不超过容量的最早位置——允许填入已排定口令之间的空档；占用按 `[开始, 结束)` 计算，零时长口令不占人手。面板列出每条口令的开始 / 结束时刻与用人数、总工期，并附迷你甘特图。图中存在环时面板停止输出班组结果、改为显示现有成环路径（原排程与模拟仍按原规则运行）。班组人数与用人数随项目沿 `/api/project` 一起保存并由后端校验（旧数据默认班组人数 1、用人数 0）。
- **增量预演（不保存）**：选中口令（持续时长）或前置约束（等待秒数）后，在侧栏「增量预演」中输入**不小于当前值**的试算秒数，系统在内存克隆的口令图上即时试算，并排展示现行与试算的**总工期**、**开场截止超期量**（未启用开场截止时显示“未启用”），并列出**开始时刻实际被推迟的口令及推迟秒数**；每条推迟口令附一条从改动点沿被拉紧约束传播而来的前驱路径（路径上标注各约束等待秒数），等长路径按边 ID 稳定选取一路。若改动被浮动余量完全吸收则提示无口令推迟。预演全程不触发保存：只有点击「应用」才沿现有编辑链写入并保存，「取消」直接丢弃，模拟中的已执行记录保持不变。当前图存在环时预演区提示无法试算并展示成环路径，排程回退与红色高亮不受影响。
- **模拟执行**：「开始模拟」按当前**原排程**（无容量约束的最早开始时间）推进时钟；可暂停、继续、重置。班组排程面板独立展示，不改变原排程与模拟。模拟期间修改口令图，仅尚未执行的口令按新排程更新，执行中与已完成的口令保持原记录。
- **视图**：拖动空白处平移，滚轮缩放；底部甘特图展示排程与执行进度，启用截止后叠加截止时刻虚线与各口令的浮动窗口。

## 本地开发（可选）

```bash
# 终端 1：后端（http://localhost:8080）
cd server && npm install && npm run dev

# 终端 2：前端（http://localhost:5173，/api 已代理到 8080）
cd client && npm install && npm run dev
```

## 技术栈与结构

- 前端：React 18 + TypeScript + Vite（SVG 图编辑器、甘特图）
- 后端：Node.js + Express + TypeScript（JSON 文件持久化，原子写入）
- 部署：多阶段 Dockerfile + Compose（命名卷 `sandbox-data` 持久化口令图）

```
├── Dockerfile            # 三阶段：前端构建 → 后端构建 → 生产运行时
├── docker-compose.yml    # 单服务，映射 8080，挂载数据卷
├── client/               # React 前端
│   └── src/
│       ├── schedule.ts       # 拓扑排程 + 截止倒排（关键链）+ 环路径检测 + 班组排程（computeCrewSchedule）+ 增量预演（runWhatIf）
│       ├── useSimulation.ts  # 模拟时钟（暂停/继续/重置/增量同步）
│       ├── GraphCanvas.tsx   # SVG 口令图编辑器
│       ├── CrewPanel.tsx     # 班组排程面板（起止时刻、用人数、总工期、迷你甘特图）
│       ├── CyclePath.tsx     # 成环路径展示（侧栏与班组面板共用）
│       ├── Timeline.tsx      # 甘特图
│       └── SidePanel.tsx     # 属性编辑侧栏（含用人数）+ 增量预演（现行/试算对比、推迟路径、应用/取消）
└── server/               # Express 后端
    └── src/index.ts          # /api/project 读写 + 班组人数/用人数校验 + 静态托管
```

## 配置

- 端口由 Compose 固定映射为 `8080:8080`（容器内读环境变量 `PORT`，默认 8080）；访问地址：**http://localhost:8080**。
- 数据保存在命名卷 `sandbox-data`（容器内 `/app/data/project.json`）；首次启动自动写入示例口令图（含班组人数 2 的容量冲突示例）。删除卷即恢复示例：`docker compose down -v`。
- 班组相关字段：项目级 `crewSize`（正整数），口令级 `crew`（非负整数且 ≤ `crewSize`）；旧数据缺省时分别按 1、0 处理。
